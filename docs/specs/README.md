# Спецификации системы Corporate

Набор документов, по которым систему Corporate можно воссоздать с нуля. В отличие от обзорных [specification.md](../specification.md) (что система делает) и [architecture.md](../architecture.md) (как устроена), документы этого каталога спускаются до уровня реализации: контракты HTTP API, схемы данных по полям, экраны админ-панели, алгоритмы RAG и DLP, значения конфигурации.

## Состав

| Документ | О чём |
|---|---|
| [ai-server.md](ai-server.md) | Сервер ассистента (форк LibreChat): конфигурация, политика доступа, RAG-конвейер, DLP, лимиты и учёт расходов, память, инструменты, office API, синхронизация справочника |
| [admin-api.md](admin-api.md) | Сервис сотрудников на Go: доменная модель, схема PostgreSQL, HTTP API, интеграция с Keycloak, фоновые процессы, команды CLI, конфигурация |
| [admin-ui.md](admin-ui.md) | Админ-панель на React: стек и сборка, OIDC-аутентификация, маршрутизация, клиент API, экраны разделов, интернационализация и темы |
| [data-model.md](data-model.md) | Полная модель данных: корпоративные коллекции MongoDB по полям и индексам, таблицы PostgreSQL сервиса сотрудников, векторный индекс |
| [api-reference.md](api-reference.md) | Сводный справочник HTTP-контрактов: office API сервера ассистента, приём уведомлений, API сервиса сотрудников |
| [deployment.md](deployment.md) | Развёртывание: манифесты Kubernetes, realm Keycloak и клиенты, MinIO, локальные эмбеддинги, секреты и переменные окружения |

## Как читать для воссоздания

1. Начните с [specification.md](../specification.md) и [architecture.md](../architecture.md) — они дают назначение, роли, компоненты и основные потоки.
2. Модель данных ([data-model.md](data-model.md)) первична: на неё опираются все три сервиса.
3. Сервисы независимы и собираются по своим документам: сервер ассистента, сервис сотрудников, админ-панель.
4. Контракты их взаимодействия — в [api-reference.md](api-reference.md); их проверяют обе стороны.
5. Запуск стенда целиком — по [deployment.md](deployment.md) и [deploy/README.md](../../deploy/README.md).

## Обозначения

- Пути вида `ai/packages/api/src/...`, `admin-api/internal/...`, `admin-ui/src/...` указывают на расположение реализации в репозитории.
- Идентификаторы (имена полей, маршрутов, переменных окружения, констант) приводятся так, как они заданы в коде.
- Роли ассистента: `OWNER`, `ADMIN`, `HEAD`, `USER`. Признаки справочника: «Админ» (`is_admin`), «Руководитель отдела» (`is_head`).
